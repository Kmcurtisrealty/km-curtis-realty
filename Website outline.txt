# KM Curtis Realty — Claude Code Website Master Specification

## WEBSITE REFERENCE & DESIGN DIRECTION

### Reference Website

Use the following website as a **UX, information architecture, functionality, and visual-quality reference**:

https://jeanniemillerannapolis.com/properties

The specific reference section is the Portfolio / Properties experience.

The goal is to create a website for KM Curtis Realty that has a similar level of sophistication, organization, property presentation, and user experience.

### IMPORTANT — DO NOT CLONE THE WEBSITE

Use the reference site only as inspiration for:

* Overall quality
* Information architecture
* Property presentation
* Listing cards
* Featured listings
* Past transactions
* Property search
* Community/location pages
* Lead-generation structure
* Navigation concepts
* CTA placement
* Premium real estate aesthetic
* Individual property detail pages

Do NOT copy:

* Text
* Images
* Logos
* Branding
* CSS
* Source code
* Proprietary design elements
* Exact layouts
* Testimonials
* Property information
* Client information

The finished website must be an original KM Curtis Realty experience.

# 31. MLS / IDX

Do not scrape another real estate website.

Do not scrape MLS listings.

Do not manually copy live listing data from third-party websites.

Create an integration-ready architecture.

The actual MLS / IDX provider will be selected separately.

When an IDX provider is selected, build the integration according to that provider's API and licensing requirements.

# 43. CLAUDE CODE INSTRUCTION

When implementing this project:

First inspect the repository and determine what already exists.

Then create an implementation plan.

Before building the property system, establish:

1. Property data model
2. Property card component
3. Property grid
4. Search/filter component
5. Property detail template
6. Community data model
7. Community page template
8. Lead form architecture

Build these as reusable components rather than one-off pages.

The property system should be designed so that an IDX/MLS integration can replace the demo data later without requiring a complete rewrite of the frontend.

Do not begin by creating dozens of static property pages.

Build the underlying system first.
